# Paired Mutual-TLS Transport

SyncGate's direct TCP transport uses TLS 1.3 with mutual authentication. Each
agent presents a short-lived X.509 certificate whose Ed25519 key is the device
identity established during pairing.

## Identity binding

The certificate subject and other display names are not identity sources. They
are deliberately empty in certificates generated by SyncGate. After the TLS
proof-of-possession exchange, each endpoint:

1. requires exactly one Ed25519 peer certificate;
2. checks its validity window, digital-signature usage, role usage, signature,
   and the `syncgate/1` application protocol;
3. computes the fingerprint and device ID from the certificate public key;
4. reloads that device from the local pairing database;
5. requires trusted state and an exact public-key and fingerprint match; and
6. on outbound connections, compares the derived ID with the explicitly
   expected peer device ID.

Unknown, pending, revoked, expired, not-yet-valid, malformed, or mismatched
peers fail the handshake. The listener completes this verification before it
publishes a session to the application. `Session.RemoteDeviceID` is populated
only after successful verification and is derived from the certificate key,
never from a caller field or certificate name.

SyncGate pins the paired Ed25519 public key, rather than one exact generated
certificate. This permits certificate renewal without changing device identity.
TLS session tickets are disabled, and the trusted-device database is consulted
for every new handshake, so revocation blocks new sessions. This slice does not
forcibly terminate a stream that completed authentication before revocation;
per-action authorization and revocation rechecks belong to the authenticated
session authorization layer.

## Manual transport workflow

Both commands use the identity and trust database selected by the configuration.
The peers must complete pairing first.

Receiver:

```powershell
syncgate receive-once --config config.json --listen 127.0.0.1:47821 `
  --share-root C:\SyncGate\Drop
```

Sender:

```powershell
syncgate send-once --config config.json --addr 192.0.2.10:47821 `
  --peer ABCD-EF01-2345-6789 --file report.pdf --relative-path report.pdf
```

The sender must name the expected paired receiver. The receiver accepts only
trusted paired identities. Share capability authorization is not attached to
this manual transfer path until the next slice.

## Security scope

TLS authenticates and encrypts the direct TCP connection between the two agent
processes for the lifetime of that connection. It does not provide file-level
encryption, encrypted data at rest, anonymous transport, or a general claim of
end-to-end encryption through a future relay or coordinator. A future relay is
end-to-end protected only if it forwards an opaque TLS connection without
terminating or replacing this authenticated peer session.
