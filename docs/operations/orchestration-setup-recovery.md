# Orchestration Setup Recovery and Disable Procedure

The shipped daemon exposes orchestration setup inventory only. Runtime
execution and workspace allocation are disabled, and authority-service routes
for graph publication, validation, context/runtime preflight, and contract
preview return sanitized `503 unavailable` responses until an explicitly
configured authority service is released.

## Release gate

Run the machine-checkable gate from the repository root:

```powershell
powershell -ExecutionPolicy Bypass -File tools\check_orchestration_setup_release.ps1
```

It runs formatting and the full suite, vet, architecture-boundary tests, short
fuzz smoke tests for portable records, graphs, envelopes, and scopes, and the
focused race suite when CGO is available. A `CGO_ENABLED=0` result is an
explicit skip, not a passing race result; use Linux CI or another C-enabled
host before a release.

## Recovery

1. Stop the daemon cleanly. Do not edit or delete `.agent-project/` canonical
   records, immutable registry/contract/intake rows, or result envelopes to
   force a retry.
2. For project read-model damage, use the supervised project rebuild endpoint
   or restart the daemon and rebuild from the validated portable records. Task
   readiness is reconstructed from task/graph/work-package records and
   canonical work events.
3. Context bundles are local cache files under
   `.agent-project/local/context-cache/`. A canceled compile writes no cache;
   a missing or damaged cache is regenerated by compiling the same declared
   sources. A byte conflict fails closed.
4. Result-intake decisions are local durable authority state. On restart,
   replay the exact same envelope only; the stored result ID and digest return
   the prior idempotent decision. A different digest or idempotency reuse is a
   conflict and requires operator investigation, not deletion.
5. For portable-record compatibility failures, keep the original bytes in the
   project directory, upgrade the target daemon, and rebuild. An older daemon
   may transport supported bytes but must not project unknown semantics into
   readiness or schedule work.

## Disable and containment

- Leave `runtime_execution_enabled` and `workspace_allocation_enabled` false.
  Do not replace the shipped disabled setup facade with a runtime adapter as a
  recovery action.
- If a future authority service is enabled and a boundary violation is
  suspected, stop the daemon, remove that service from composition, restart,
  and verify `GET /api/v1/orchestration/capabilities` reports both flags false.
- Treat a result-envelope, contract, registry, or telemetry binding conflict
  as untrusted input. Preserve its identifiers and sanitized error code for
  audit; do not publish a canonical success event from it.
- Keep sync and transport operating only as byte transfer. They must not start,
  resume, cancel, or accept runtime execution.
